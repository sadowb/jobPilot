# modules/runs

Read the [root AGENTS.md](../../../../AGENTS.md) first (layering, logging, schema rules).

- **Owns**: run, run_event, approval
- **Files**: `runs.controller.ts` (IPC), `runs.service.ts`, `runs.repository.ts`, `runs.entity.ts` (contract, exists), `runs.dto.ts` (zod input/output; shared row types go in `src/shared/dto/`).
- **Notes**: Owns run lifecycle: queue runs by leaving them `queued` (the `run` table is the queue; `ApplyWorker` slots claim them atomically, ADR 0017). Startup requeues `running` rows under 3 attempts for a native Claude session resume and fails the rest, then starts the queue paused (`runs.paused`, also set by an owner pause or by a quit that re-queued in-flight runs) until the owner resumes; a heartbeat (`progress_at`) feeds the stuck watchdog, which moves a silent run to `needs_you`, call the AgentProvider + BrowserProvider, validate `RunResult` with zod, apply the transition. Submit requires an `approval` bound to `form_hash` (ADR 0020): `approve` re-reads the live form, fails closed and refills on any difference, wins one conditional UPDATE (idempotent), then a detached submit run clicks once under a durable `submit_claimed_at` claim; an unconfirmed click is a failure, never a retry. Owner answers go to `application_answer` (source `owner`) and the application is filled again. Auto mode is not built. One active run per application is enforced by the partial unique index; handle its violation as "already running", not as a crash.

Take over (#243): `takeOver` holds the run's tab (running or awaiting_approval only), `handBack` releases it, `goToTab` returns the tab's page id and host. `approve` is refused while held, so the owner's own edits are never sent unreviewed: after hand back the form hash differs and approve refills. Nothing in this path submits (ADR 0020 unchanged).
