# modules/onboarding

Read the [root AGENTS.md](../../../../AGENTS.md) first (layering, logging, schema rules).

- **Owns**: the P1 pre-flight (detect agents and browser tools, "Allow both"), the P2 CV reader and the agent-led About-you chat turn, and nothing else. P3 and the profile saves are renderer-side over the existing profile IPC.
- **Files**: `preflight.service.ts` (detection + allow/test, calls `GrantsService`), `cv.service.ts` + `cv-text.ts` (PDF only, via `unpdf`, parsed in a utility process; magic bytes decide the format, 60k character cap), `cap-turn.service.ts` (one chat turn: input `{history, known, missing, text|null}`, output `{reply, facts, settled, suggestions}`; `text: null` is Cap's opener; `settled` is filtered to the keys in `missing`), `structured-call.ts` (tool-less, ephemeral agent call with a zod output schema), `onboarding.controller.ts` (IPC, native file picker for a custom agent).
- **Notes**: the CV is untrusted data in the prompt, never instructions; every agent output is parsed with zod and nothing is saved here. The renderer holds the extraction as a draft and commits it to the profile only on "Ready for take-off". Models are listed from the agent at runtime (`agent.service.models()`), never hard-coded; Opus is filtered out. All agent calls go through the gated provider (see `modules/grants`).
- **Chat contract**: the app owns _what_ is needed (`missingItems` in the renderer's `draft.ts`: name, email, phone, location, nationality, markets, `lang:<id>`, `rights:<code>`) and enables "Ready for take-off" only when it is empty; the agent owns _how_ it asks and extracts. Facts are allow-listed (`personal`, `language`, `market`, `nationality`, `work_auth`; work rights are per country, nationality is global) and re-validated in the renderer (`applyFacts`), which drops invalid values. History, known summary, missing list and owner message are untrusted data in the prompt. Nothing is saved until the final press.
