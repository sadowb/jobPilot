# ADR 0012: Packaged app and upgrade verification

- Status: accepted
- Decision: Require four CI tiers. Tier 1 runs on `ubuntu-latest`: dependency install, typecheck, lint, formatting, existing `npm test` guardrails, Gitleaks, high severity npm audit, and database checks. Tier 2 builds and smoke-checks native SQLite on `macos-14`. Tier 3 packages the `.app`, then runs the same Playwright journey against the dev app and packaged app plus an upgrade journey from the PR base using the same temporary user data directory. Tier 4 runs nightly live ATS probes and is also manually dispatchable. Releases run tiers 1–3, build an arm64 DMG, attach checksums to a draft release, and require an owner to publish it.
- Rationale: Source and dev builds do not represent the shipped app. The app crashed because Drizzle required `better-sqlite3` while the package contained only `better-sqlite3-multiple-ciphers`. The first backup failed because the private native backup handle produced an incompatible source/target database. Packaging catches the first class; encrypted backup assertions and upgrade-from-base journeys catch the second and migration ordering failures.
- Consequence: No unit tests are added (ADR 0011). Behaviour coverage stays in real-app journeys. Every feature PR exercises its packaged feature, every bug fix adds its regression assertion, and `npm run verify` is the local parity command. Playwright uploads traces, screenshots, and user data logs only on failure. The macOS job is gated behind static checks and targets an eight minute wall-time budget; its duration is reported in the Actions summary.
- Risk: The app uses ad-hoc macOS signatures. Electron documents that `safeStorage` may prompt again when updates do not share a stable signature. Upgrade launches have hard timeouts so a Keychain prompt or hang is surfaced; release signing needs a stable identity before distributing updates broadly.
- Test harness: Playwright's Electron launcher requires Node inspector support to evaluate main-process storage assertions. `scripts/run-e2e.mjs` temporarily enables only the Node CLI inspector fuse on the packaged `.app` and PR-base `.app`, then restores it in a `finally` block before any release artifact is created. The shipped app retains the inspector fuse off.
- Backup evidence: SQLite3 Multiple Ciphers documents cipher and key URI parameters, including use for a `VACUUM INTO` destination: [URI parameters](https://utelle.github.io/SQLite3MultipleCiphers/docs/configuration/config_uri/) and [SQL pragmas](https://utelle.github.io/SQLite3MultipleCiphers/docs/configuration/config_sql_pragmas/). The native smoke check verifies encrypted header bytes, opening with the key, and rejection without it.
- Shipped bytes: the Playwright journeys run on a copy whose inspector fuse is temporarily on, so they are not the final proof. `scripts/verify-shipped.mjs` checks the unmodified `.app` after the journeys: hardening fuses (RunAsNode, NODE_OPTIONS, inspector off; cookie encryption, ASAR integrity, ASAR-only on), `codesign --verify --deep --strict`, and a 15 s real boot with a temp profile that must create an encrypted, owner-only `jobpilot.db` and no error-level logs. It runs in CI, `npm run verify`, and release, where the DMG is built `--prepackaged` from that same verified `.app`. When ADR 0014 signing lands, `run-e2e.mjs` must re-sign with the stable certificate instead of ad-hoc.
- Supply chain: workflow actions are pinned to commit SHAs (node24 majors) and bumped by Dependabot; the release workflow, which has `contents: write`, never restores the shared npm cache.
