# ADR 0016: Gentle footprint on the owner's Mac

- Status: accepted (2026-10-23, amended 2026-10-23).
- Decision: JobPilot is a guest on the owner's Mac. Every lane and review must enforce the rules below.
- Context: The owner's principle in [#70](https://github.com/sadowb/jobPilot/issues/70): “I don't want the app to be intrusive to someone's system, it needs to be gentle.”
- Precedence: This decision amends ADR 0003's default concurrency and ADRs 0004 and 0015's Claude provisioning/authentication decisions wherever they conflict with these rules. ADR 0015 still governs explicitly selected, JobPilot-owned MCP tools under `userData`; it does not authorize changes to the owner's installed tools.
- Amended 2026-10-23 ([#88](https://github.com/sadowb/jobPilot/issues/88)): Parallel runs default to six (liteque default restored). Owner's Claude login is the default across all builds (API key remains an option in Settings → Agent). BrowserOS Neo remains the default browser with one tab per parallel run.

## Binding rules

1. **Read tools, never rewrite them.** Detect installed `claude` (and later codex/agy) with `--version` only. Never edit `~/.claude`, user settings, hooks, plugins, MCP configuration, shell rc files or PATH. Never install, upgrade or log in the owner's tools on their behalf. If a tool is missing, incompatible or unauthenticated, show a hint for the owner to act on.
2. **Leave no transcripts or ambient configuration behind.** Claude runs must pass `--no-session-persistence` (the issue records support in Claude 2.1.303); SDK adapters must emit the same flag. Set `settingSources: []`, load no user settings, hooks or plugins, and accept only explicitly scoped MCP configuration. Working directories are private, under `userData/agents/<run-id>/`; all writable config, caches and temporary state must also stay under `userData`. A CLI without these isolation guarantees cannot be enabled. JobPilot's own run records remain subject to its data-removal action, not the CLI's session store.
3. **Own one data directory.** DB, logs, backups, agent workspaces, downloads, caches and tools state all live inside JobPilot's `userData`. The only other writes are files the owner explicitly exports to a chosen destination. Settings must offer **Remove all JobPilot data**, with confirmation: stop work, close tabs and child processes, close DB/log handles, then delete the data directory without immediately recreating it. Remove JobPilot's own Keychain item as part of reset; never delete another app's data or credentials.
4. **No unsolicited background presence.** No login item, LaunchAgent, menu-bar tray, global shortcuts or power-save blocker. Quitting fully quits: stop admitting work, drain the queue's shutdown work, abort active runs, kill child processes (including descendants), close only JobPilot-owned Neo tabs, and close storage. Pending jobs must not keep a worker alive after quit. Cancel performs the same run-scoped cleanup, including on errors and timeouts.
5. **Use resources politely.** Parallel runs default to **four**, configurable by the owner (1–32) (amended by [ADR 0017](0017-run-table-as-queue.md)). Provide an optional setting to pause new work on battery saver or low battery; define and show its threshold, and resume only work paused for that reason. Child processes run at normal or lower priority. Backups and maintenance run when idle and yield to interactive work.
6. **Keychain: one item, asked once.** Use only the safeStorage item JobPilot creates; reuse it across launches and updates with the stable signing identity in ADR 0014. Never enumerate or read other items. Encrypted JobPilot secret files belong under `userData`, not additional Keychain entries. The installed Claude CLI reads its own login; JobPilot never reads or copies it. An explicitly supplied API key may be an optional fallback, not a requirement to use an existing CLI login. Do not repeatedly prompt after denial; show an actionable hint.
7. **Restrict network access.** Runtime traffic goes only to job sites the owner added, the owner's selected agent provider, and the Releases update check. Settings must allow disabling that update check. No telemetry. ADR 0015's explicit, observable tool installation is a separate owner-requested download, limited to its pinned official artifacts; it cannot become an automatic run-time download or update.
8. **Own only run tabs.** Open tabs only for JobPilot runs, record their ownership and close them on cancel and quit. Never enumerate, control or close unrelated tabs, or read/change the owner's cookies or browser profile. If a provider cannot isolate run access, block it with a hint rather than granting broader browser access.

## Enforcement and verification

The root `AGENTS.md` links this decision; the PR template requires the gentle-footprint review line for every lane. Reviews inspect write destinations, subprocess environments/arguments, network destinations, tab ownership and shutdown paths. An exception needs an explicit superseding ADR, not an implementation shortcut.

This is a policy change, not proof that the current app implements every rule. Follow-up implementation must reconcile Claude provisioning and authentication with ADR 0004/0015, explicitly disable session persistence (the current adapter already sets `settingSources: []`), wire private run directories, implement full data removal and lifecycle cleanup, apply and calibrate the concurrency default, and expose battery/update preferences. No hardware calibration or Keychain prompt behavior was verified for this ADR.

Each implementing feature or fix must add packaged-app journey evidence under ADR 0012: isolated userData and sentinel tool configuration remain untouched; CLI arguments/environment prevent persistence and ambient configuration; cancel/quit leave no owned children or tabs; unrelated browser state survives; reset removes owned data only; battery pause and disabled update checks prevent their respective work. Settings changes also save light/dark screenshots under the Playwright output directory per `e2e/AGENTS.md`. These assertions belong with the implementing changes; this documentation-only decision adds no app behavior or journey.

## Consequences

JobPilot may block a provider that cannot meet these boundaries and may trade throughput for a responsive Mac. The owner handles their own tool installation and login. On-demand app-owned tools remain removable with JobPilot data. CI green is necessary, but does not substitute for the footprint review or the base-Mac resource measurement.
